# Ingest a Source into the Knowledge Base

Ingestion is the core write operation of the LLM wiki: take raw material, snapshot
it immutably for provenance, then **distill** it into structured, cross-linked
concept pages so future work reads the compiled knowledge instead of
re-discovering it. Read `${CLAUDE_PLUGIN_ROOT}/references/okf-spec.md` and `${CLAUDE_PLUGIN_ROOT}/references/llm-wiki.md` if
you need the model.

The guiding principle is **compounding**: prefer updating existing pages and
adding cross-links over creating near-duplicates. A source is not "filed" until
its durable knowledge lives in concept pages, not just in `raw/`.

## Workflow

### 1. Acquire the source

Get the actual content:
- **File / PDF** — read it (use the `pdf` skill for PDFs).
- **URL** — fetch it with WebFetch.
- **Conversation / notes** — use the material already in context.

Note the canonical origin (URL, file path, or "conversation on <date>") — it
becomes the `resource` and a citation.

### 2. Auto-detect the target domain

Distill the source to its key topic terms (title, named systems/entities,
keywords), then rank domains:

```bash
pwsh -File "${CLAUDE_PLUGIN_ROOT}/scripts/detect_domain.ps1" \
  --query "stripe webhook signature verification hmac retry" --json
```

The script returns a ranked list with a `confidence` signal. Use it as a
baseline, then apply your own semantic judgement — you can read domain scopes
with `--list`:

- **high** and it matches your reading → ingest into that domain.
- **medium / low / ambiguous** → open the top domains' `domain.md` scope sections
  and decide. If genuinely unclear between two, ask the user.
- **no domain fits** → create one first with the `kb-init-domain` skill, then
  continue. Don't force an unrelated source into an existing domain.

Detection is recursive: a recommendation may be a **nested sub-domain** such as
`billing/eu`. Prefer the most specific matching (sub-)domain — it keeps related
knowledge together. Pass the full slug wherever a domain is expected (search and
lint accept nested paths, e.g. `--domain billing/eu`). If a source clearly needs
a narrower home that doesn't exist yet, create a sub-domain with `kb-init-domain`
before ingesting.

A source may legitimately touch two domains — ingest the primary knowledge into
its best home and add a cross-link from the other, rather than duplicating pages.

### 3. Snapshot the raw source

Write an immutable snapshot under the domain's `raw/`:

`kb/<domain>/raw/<source-slug>.md`

```markdown
---
type: Source
title: <source title>
description: <one line on what it is>
resource: <original URL or path>
tags: [<domain tags>]
timestamp: <ISO 8601 now>
---

# Source

<A faithful extract or the key excerpts. Preserve enough to re-derive the concept
pages later. Do NOT edit this file after writing it — it is the provenance record.>
```

Add the source to `kb/<domain>/raw/index.md`.

### 4. Distill into concept pages — search before you write

Knowledge compounds only if you extend what exists. **First search** the domain
for pages the source touches:

```bash
pwsh -File "${CLAUDE_PLUGIN_ROOT}/scripts/kb_search.ps1" "<key concept>" --domain <domain>
```

Then, for each durable concept the source establishes:
- **Existing page** → update it: add facts, refine, add citations. If the source
  contradicts it, reconcile (correct the page and note the change in `log.md`) —
  don't leave two conflicting claims.
- **New concept** → create `kb/<domain>/<concept-slug>.md`:

```markdown
---
type: <Reference | Playbook | Entity | Metric | …>
title: <Concept name>
description: <one sentence>
resource: <URI if it describes a concrete asset; omit for abstract concepts>
tags: [<tags>]
timestamp: <ISO 8601 now>
---

# <Structural sections: Overview, Schema, Steps, Examples…>

Use headings, tables, and lists over prose — structure aids retrieval. Link
related concepts with bundle-relative markdown links, e.g.
[retry policy](/<domain>/retry-policy.md).

# Citations

[1] [<source title>](/<domain>/raw/<source-slug>.md)
```

Guidelines:
- One concept per page; the file path is its identity.
- Distill meaning, don't copy the source — the raw snapshot already holds the
  verbatim material.
- Wire in cross-links generously (both directions where it makes sense).
- Cite the raw snapshot (and external URLs) under `# Citations`.

### 5. Update index and log

- Add new concept pages to `kb/<domain>/index.md` (title + description), or run
  `pwsh -File "${CLAUDE_PLUGIN_ROOT}/scripts/kb_lint.ps1" --domain <domain> --fix-index`
  to regenerate the concept list.
- Prepend a dated entry to `kb/<domain>/log.md` (newest first, ISO date):

  ```markdown
  ## 2026-07-18
  * **Ingest**: Added [signature verification](/billing/signature-verification.md)
    from [Stripe webhooks doc](/billing/raw/stripe-webhooks.md).
  ```

### 6. Verify and report

Run a scoped lint and fix easy issues:

```bash
pwsh -File "${CLAUDE_PLUGIN_ROOT}/scripts/kb_lint.ps1" --domain <domain>
```

Then tell the user, concisely: which domain received it, which pages were created
vs updated, and any follow-ups (e.g. contradictions found, a thin page worth
expanding later).

## Anti-patterns

- Dumping the raw source as a "concept page" without distilling it.
- Creating a new page when an existing one should be extended (breaks compounding).
- Ingesting ephemeral chatter — capture durable, reusable knowledge, not
  transient back-and-forth.
- Fabricating detail the source doesn't support. If unknown, leave it out or mark
  it as open.
